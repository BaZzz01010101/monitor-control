## High-Value Takeaways

- Slint UI is declarative and reactive. Prefer bindings and computed properties over imperative UI updates.
- Use layouts for sizing and positioning. Elements outside layouts usually need explicit `width` and `height`.
- Favor reusable custom components with `in`, `out`, and `in-out` properties over ad-hoc inline UI.
- Use `changed` callbacks sparingly. If a relationship can be expressed as a binding, use the binding instead.
- Long, scrollable collections should use `ListView` and data models instead of large `for` loops in a `ScrollView`.
- Core visual primitives are `Rectangle`, `Text`, `Image`, `Path`, and `StyledText`; standard widgets build on top of them.
- Keyboard handling, focus, gestures, windows, dialogs, popups, and menus all have dedicated reference sections and built-in types.
- Styling is split between common properties, colors/brushes, built-in widgets, palettes/style metrics, and custom controls.
- Tooling support exists for VS Code, Zed, JetBrains IDEs, Qt Creator, NeoVim, Helix, Kate, and manual LSP setup.
- Platform guidance is separate for desktop, embedded, Android, iOS, web, and renderer/backend selection.
